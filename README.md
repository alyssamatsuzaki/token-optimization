# Tokop

**Measure the cheapest LLM pipeline that still meets your quality bar.**

Tokop records an LLM workload, finds expensive prompt and routing choices, builds lower-cost
candidates, and compares the best candidate with the current pipeline on held-out tasks. It reports
cost per successful task, confidence intervals, a non-inferiority verdict, and the cost of running
the evaluation.

The application runs locally and includes deterministic fixtures, so you can try the complete
workflow without an API key or network access.

## Start the demo

**Requirements:** Python 3.12, [uv](https://docs.astral.sh/uv/), Node.js, and
[pnpm](https://pnpm.io/).

```bash
make setup
make demo
```

Open [http://localhost:8000](http://localhost:8000). The initial report takes several seconds to
build and is then cached for the life of the server.

For frontend hot reload, run `make dev` and open [http://localhost:5173](http://localhost:5173).

## Product tour

| Area | What it does |
| --- | --- |
| **Optimize** | Measures the current pipeline, ranks findings by dollars, builds a candidate, and presents the held-out proof. Every disagreement opens to the underlying trace. |
| **Inspect** | Estimates prompt cost across models, checks cacheability, highlights prompt problems, and previews deterministic fixes as a diff. It also includes brief and multi-turn session analysis. |
| **Compare** | Shows responses, token usage, cost, time to first token, and latency side by side. A manual column supports answers copied from subscription applications. |
| **Spend** | Breaks the local ledger down by day, provider, workload, model, pipeline, and split. Scarce-model usage is tracked separately. |
| **Settings** | Shows runtime mode, budgets, provider availability, model prices and provenance, and controls for deleting stored prompt and response content. |

Tokop exports a prompt diff, cascade configuration, and routing rule for your application to adopt.
It is not a gateway and does not sit in the production request path.

## How it works

1. **Record or replay.** The runner renders each task, calls a provider adapter, normalizes usage,
   applies a price snapshot, grades the answer, and stores the trace. Failed calls remain visible
   and count as unsuccessful tasks.
2. **Find waste.** Deterministic lint and workload findings identify expensive prompt layout,
   output, caching, and graph choices. Findings are ordered by projected savings rather than style.
3. **Build candidates.** Transforms improve cache placement and output contracts. A model cascade
   can try cheaper tiers first and escalate uncertain answers.
4. **Calibrate.** Scorers choose routing thresholds on the calibration split. Scorers cannot access
   gold answers; grading is implemented and tested separately.
5. **Prove.** The selected candidate and baseline run on the same held-out tasks. Tokop computes
   accuracy intervals, paired cost intervals, an exact McNemar test, and the non-inferiority result.
6. **Export and monitor.** Exported artifacts apply the measured change. Provenance, certificates,
   fingerprints, and canaries describe when the result no longer applies.

For workloads without a complete answer key, Tokop can combine a cheap judge over all tasks with a
strong grader over a sampled subset. The corrected estimate measures the cheap judge's bias; poor
judge quality widens the interval rather than silently defining correctness.

## Use your own workload

Workloads are YAML files that reference a JSONL dataset and optional grounding material. They define
the calibration/test split, prompt pipelines or graph steps, grading method, non-inferiority margin,
cascade tiers, scorer features, allowed providers, and provenance.

Start with [`data/demo/workload.yaml`](data/demo/workload.yaml) and [`docs/DATASET.md`](docs/DATASET.md).
The engine supports JSONL, CSV, and OpenTelemetry ingestion; the browser does not yet include a
general upload wizard.

```bash
tokop ingest --help
tokop build-test-fixtures --workload path/to/workload.yaml
tokop prove --workload path/to/workload.yaml
tokop export --workload path/to/workload.yaml
```

Run `tokop <command> --help` before using a command. `tokop report` and `tokop lint` currently use
the default demo report.

## Replay and live modes

**Replay mode** is the default. It uses committed cassettes, makes no provider requests, and disables
live controls with an explanation. A missing cassette is an error; replay never falls back to a
billable call.

**Live mode** requires explicit credentials and budgets. Copy `.env.example` to `.env`, set
`TOKOP_MODE=live`, and configure only the providers you intend to use. API keys remain on the server.

- `DAILY_BUDGET_USD` caps user-initiated live actions.
- `RECORD_BUDGET_USD` is separate consent for `tokop record` to spend up to that amount.

Before recording, Tokop checks statistical power, prints a projection, asks for confirmation, runs
a small pilot, updates the projection from measured output lengths, and enforces the cap per call.
Review [`docs/DATASET.md`](docs/DATASET.md) before running `make record`.

| `export` | Write the prompt diff, cascade configuration, or routing rule. |
| `models`, `sync-models` | Inspect or update the model and price registry. |

## Architecture

FastAPI serves `/api/*` and the built React application from one process. SQLite stores the local
ledger; there is no queue or worker.

```text
Browser / CLI
    └─ report builder: lint, cascade search, proof, evidence, export
        └─ workload runner: render, call, normalize, price, grade, record
            └─ provider adapters: Anthropic, OpenAI-compatible, cassette, simulated
                └─ core: usage, pricing, tokens, statistics, budgets, registry
```

`optimize/report.py:build_report()` is the only source of headline metrics. The API, CLI, browser,
and generated documentation all consume its result. Runs use content-addressed price snapshots, so
later price changes do not alter historical reports.

Configuration lives in `config/providers.yaml`, `config/models.yaml`, and `config/prices.yaml`.
See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for module details.

## Limitations

- Text only; image, audio, and video requests are refused rather than mispriced.
- Prompt lint is lexical and structural; it does not detect paraphrases.
- A cascade requires calibration labels or an explicitly reported judged substitute.
- Judged evaluation is relative to its strong grader, not absolute truth.
- The polished browser workflow currently uses the included demo workload.
- The committed result is simulated and has no real-traffic coverage.
- Tokop exports changes; it is not a production gateway or multi-user hosted service.

Tokop uses official provider APIs only. It does not automate consumer applications, reuse
subscription credentials, pool accounts, or evade rate limits.
